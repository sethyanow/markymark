### BLOCKER: CI fails on Linux — `toolchains_llvm_bootstrapped` glibc bootstrap

The `bazel-build-and-test` CI job fails on `ubuntu-latest` with:
```
gcc: error: unrecognized command-line option '-nostdlibinc'
```

`toolchains_llvm_bootstrapped` tries to bootstrap glibc using system GCC, which chokes on clang-specific flags. Bumping from 0.3.1 to 0.5.9 did NOT fix it (run 23614853203).

The user says this works in their other projects (forge). Key difference to investigate: forge uses `toolchains_llvm_bootstrapped` 0.2.4 with `apple_support` handling macOS, and only registers Linux toolchains. markymark is now on 0.5.9. **Investigate what forge does differently that makes the Linux bootstrap work.** The forge `.bazelrc` has additional flags that may matter:
- `--experimental_cc_static_library`
- `--experimental_cc_shared_library`
- `--incompatible_use_cc_configure_from_rules_cc`
- `--experimental_starlark_cc_import`
- `--compiler=clang`

These ARE in markymark's `.bazelrc` too. So either:
1. The forge version (0.2.4) has different bootstrap behavior than 0.5.9
2. Something else in the forge setup prevents the GCC bootstrap path
3. The runner environment matters (forge may use a different runner or have clang pre-installed)

**Check the forge CI workflow to see what runner and setup it uses.** Also check if forge has ever run on `ubuntu-latest` successfully with `toolchains_llvm_bootstrapped`.
