## Edge Cases
- Zig WASM target may not support all features (file I/O, threads)
- @Vector may fall back to scalar in WASM (check generated WASM bytecode)
- WASM SIMD not supported in all browsers (Safari support timeline)
- WASM memory model differs from native (no mmap, explicit memory growth)
- VS Code web extension sandboxing may limit WASM capabilities

## Anti-patterns
- NO writing production WASM code (spike only)
- NO assuming WASM SIMD works without verifying generated bytecode
- NO benchmarking WASM in debug mode (must use optimized build)
- NO ignoring binary size (WASM is downloaded, size matters)
- NO skipping the recommendation section (must give clear GO/NO-GO)
